# ToolGuard Observability Demo

This local stack demonstrates the intended production-style ToolGuard observability flow:

```text
ToolGuard demo -> OTLP -> OpenTelemetry Collector -> OpenObserve
                                      |-> Prometheus -> Grafana
                                      |-> Loki -> Grafana
ToolGuard demo -> NDJSON logs -> Promtail -> Loki
```

OpenObserve is the unified exploration UI for traces, logs, and metrics. Grafana is the polished dashboard UI for screenshots and walkthroughs. Prometheus and Loki show the production decomposition behind the dashboard.

All services bind to `127.0.0.1` and avoid ToolGuard demo ports `3660-3669` except the Core metrics server at `3660`.

## Happy path

```bash
pnpm observability:up
pnpm demo:openobserve
```

Open:

| Service             | URL                                                                        | Purpose                                       |
| ------------------- | -------------------------------------------------------------------------- | --------------------------------------------- |
| OpenObserve         | <http://127.0.0.1:5080>                                                    | Unified trace, log, and metric exploration    |
| Grafana             | <http://127.0.0.1:33000/d/toolguard-observability/toolguard-observability> | Curated ToolGuard dashboard                   |
| Prometheus          | <http://127.0.0.1:39090>                                                   | Raw metrics, rules, and alert checks          |
| Loki API            | <http://127.0.0.1:33100>                                                   | Redacted structured log backend               |
| OTLP HTTP Collector | <http://127.0.0.1:14318>                                                   | Trace, metric, and log ingestion              |
| OTLP gRPC Collector | `127.0.0.1:14317`                                                          | gRPC ingestion endpoint                       |
| Collector metrics   | <http://127.0.0.1:18889/metrics>                                           | Collector-exported OTLP metrics               |
| Core metrics        | <http://127.0.0.1:3660/metrics>                                            | ToolGuard Prometheus endpoint while demo runs |

Local logins are generated by `pnpm observability:config` and written only to `.tmp/openobserve.env`:

- OpenObserve: `OPENOBSERVE_ROOT_USER_EMAIL` / `OPENOBSERVE_ROOT_USER_PASSWORD`
- Grafana: `admin` / `GRAFANA_ADMIN_PASSWORD`

Stop the stack:

```bash
pnpm observability:down
```

Validate configuration:

```bash
pnpm observability:config
node scripts/check-observability-stack.mjs
```

## What `pnpm demo:openobserve` does

The command runs a deterministic ToolGuard session, exports telemetry artifacts, posts OTLP payloads to the Collector, and keeps a Core metrics server alive until `Ctrl+C`.

Generated files live under `runs/<runId>/`:

- `otel-traces.json`
- `otel-metrics.json`
- `otel-logs.json`
- `otel-logs.ndjson`
- `openobserve-dashboard-queries.json`

The Collector receives:

- `http://127.0.0.1:14318/v1/traces`
- `http://127.0.0.1:14318/v1/metrics`
- `http://127.0.0.1:14318/v1/logs`

Prometheus scrapes:

- ToolGuard Core `/metrics` at `host.docker.internal:3660`
- Collector self metrics at `otel-collector:8888`
- Collector-exported OTLP metrics at `otel-collector:8889`

Promtail tails:

```text
/workspace/runs/**/otel-logs.ndjson
```

## Grafana walkthrough

Open the ToolGuard dashboard and review:

1. Executive stat cards: tool calls, failures, sanitized outputs, policy blocks, and open circuits.
2. Event flow chart: overall events, tool calls, failures, and sanitization.
3. Risk rates: failure and circuit-open recording rules from Prometheus.
4. Redacted logs: Loki panels for all logs, failures, and sanitization evidence.
5. Demo instructions: command sequence and correlation-field guidance.

## OpenObserve walkthrough

Saved query definitions are versioned in `observability/openobserve/saved-queries.json` and generated into each run as `openobserve-dashboard-queries.json`.

Use these query patterns:

- Failure frequency: `SELECT data_toolName, count(*) AS failures FROM toolguard_logs WHERE event_type = 'tool.call.failed' GROUP BY data_toolName`
- Run drilldown: `SELECT _timestamp, level, event_type, trace_id, tool_call_id, message FROM toolguard_logs WHERE run_id = '<runId>' ORDER BY _timestamp ASC`
- Trace waterfall: `SELECT trace_id, span_id, parent_span_id, name, start_time, end_time FROM toolguard_traces WHERE trace_id = '<traceId>' ORDER BY start_time ASC`
- Sanitization evidence: `SELECT run_id, trace_id, tool_call_id, message FROM toolguard_logs WHERE event_type = 'output.sanitized' ORDER BY _timestamp DESC`

## Offline artifact path


This does not require the Collector, OpenObserve, Grafana, Prometheus, or Loki.

## OpenObserve direct upload fallback

The preferred path is Collector-first. If needed, upload generated OTLP JSON directly:

```bash
RUN_DIR=runs/run_demo_otel_openobserve_seed_v001
set -a
. .tmp/openobserve.env
set +a
AUTH="$(printf '%s:%s' "${OPENOBSERVE_ROOT_USER_EMAIL}" "${OPENOBSERVE_ROOT_USER_PASSWORD}" | base64 -w0)"

curl -H "Authorization: Basic ${AUTH}" -H "Content-Type: application/json" \
  --data-binary "@${RUN_DIR}/otel-traces.json" \
  http://127.0.0.1:5080/api/default/v1/traces

curl -H "Authorization: Basic ${AUTH}" -H "Content-Type: application/json" \
  --data-binary "@${RUN_DIR}/otel-metrics.json" \
  http://127.0.0.1:5080/api/default/v1/metrics

curl -H "Authorization: Basic ${AUTH}" -H "Content-Type: application/json" \
  --data-binary "@${RUN_DIR}/otel-logs.json" \
  http://127.0.0.1:5080/api/default/v1/logs
```

## Cardinality and redaction policy

Prometheus and Loki labels intentionally stay low-cardinality:

- Good labels: `service_name`, `event_type`, `level`, `environment`, `service`
- Kept in structured payloads, not labels: `run_id`, `trace_id`, `tool_call_id`

Telemetry is redacted before export. Secret-shaped values should not appear in OTLP JSON, NDJSON logs, Loki, OpenObserve, or Grafana.

## Troubleshooting

- Collector export fails: run `pnpm observability:up`, wait for containers to become ready, then rerun `pnpm demo:openobserve`.
- Grafana panels are empty: keep `pnpm demo:openobserve` running so Prometheus can scrape `http://127.0.0.1:3660/metrics`.
- Loki panels are empty: confirm `runs/<runId>/otel-logs.ndjson` exists and Promtail can read the mounted `runs` directory.
- Prometheus rules are missing: run `pnpm observability:config` and confirm `/etc/prometheus/rules/toolguard.yml` is mounted.
